# 光伏组串IV扫描台

扫描员提交组串开路电压、短路电流与填充因子，**提交时必须点选温带（高温带/低温带），漏点整笔拒收**。写入后走 PostgreSQL 通知通道叫醒独立工人，工人不轮询空转。

## 温度补偿（双温带闭区间）

- 高温带、低温带**各守一套填充因子闭区间 `[下限, 上限]`**（端点含），全场不共用一条线。
- 判定只吃**现行闭区间**，且以**工人认领那一瞬**为准：认领时在同一事务里把当时的上下限抄进该单的**认领抄本**（`ff_low_snap`/`ff_high_snap`），之后再改带，已经领走的单继续按抄本判定，不追溯。
- 温带还没设时交入的单排队等待，设带后由兜底轮询自动认领。
- 顶栏「温度补偿」专页分三格：**上格**现行温带（未设过显示"还没设温带"）、**中格**改带履历、**下格**认领抄本。
- 画面温带与入库温带同源：温带 key/标签只以后端 `GET /api/bands` 为准，列表行展示入库时的 `band_label`。
- 观察员（reader）只能翻温带、履历、抄本；改带与入队一律 403。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/bands` | 登录 | 两条现行温带及是否已设 |
| PUT | `/api/bands/{high\|low}` | writer | 改带，自动落一条改带履历 |
| GET | `/api/band-history` | 登录 | 改带履历（倒序） |
| GET | `/api/transcripts` | 登录 | 已认领单的抄本快照 |
| GET | `/api/logs` | 登录 | 扫描单列表（含入库温带与抄本） |
| POST | `/api/logs` | writer | 入队，必须带 `band_key`，漏点 400 整笔退 |

## 技术栈

- 后端：Litestar、Uvicorn、psycopg 同步写入
- 工人：`LISTEN/NOTIFY` 唤醒后认领，认领事务内 `JOIN ff_bands ... FOR UPDATE OF s SKIP LOCKED` 并写抄本
- 前端：Vue 3、Vite、nginx 反代 `/api`

## 验收场景

1. 温度补偿页把低温带闭区间改成 `[0.60, 0.65]`。
2. 录入页点「低温带」交 FF=0.68 → 认领后判**衰减**，抄本为 `[0.60, 0.65]`。
3. 把低温带改回上限 0.72（`[0.60, 0.72]`），再点「低温带」交 FF=0.68 → 判**合格**。
4. 第一笔的结论与抄本保持不变（不追溯）。
